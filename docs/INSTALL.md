# Installing GrapeStrap

> **DRAFT** — accurate as of v0.1.0-rc; wording and screenshots get a
> user-docs polish pass before the final v0.1.0 release.

GrapeStrap is a Linux-first desktop visual editor for static Bootstrap 5
sites. Every release ships four artifacts, built by CI from the tagged
commit:

| Artifact | File | For |
|----------|------|-----|
| Debian package | `grapestrap_<version>_amd64.deb` | Debian, Ubuntu, Mint, Pop!\_OS, elementary |
| RPM package | `grapestrap-<version>.x86_64.rpm` | Fedora, openSUSE, RHEL and derivatives |
| AppImage | `GrapeStrap-<version>.AppImage` | any distro, no install |
| Tarball | `grapestrap-<version>.tar.gz` | manual/portable installs |

Download from the [GitHub Releases page](https://github.com/juhriah-ops/grapestrap/releases).

Flatpak (Flathub), AUR, and Snap are planned after v0.1.0 — they do not
exist yet.

---

## System requirements

- **OS:** Linux x86_64, glibc 2.31+ (Ubuntu 20.04 / Debian 11 / Fedora 34 or newer).
- **Display server:** X11 or Wayland (auto-detected — see [Wayland](#wayland)).
- **RAM/disk:** ~1 GB free RAM for the editor; ~500 MB installed.
- **System libraries:** the standard Electron set (`libgtk-3-0`, `libnss3`,
  `libxss1`, `libasound2`, `libgbm1`, `libnotify4`, `libsecret-1-0`).
  The `.deb` and `.rpm` pull these in automatically; AppImage and tarball
  users may need to install them by hand.

---

## Debian / Ubuntu (`.deb`)

```bash
sudo apt install ./grapestrap_<version>_amd64.deb
```

The `./` prefix matters — without it `apt` searches remote repositories.
Dependencies resolve automatically. Installing registers the desktop entry,
the icon set, and the `.gstrap` file association (see
[MIME registration](#gstrap-mime-registration)).

**Update:** download a newer `.deb`, run the same command.
**Uninstall:** `sudo apt remove grapestrap` (projects and settings survive —
see [Removing user data](#removing-user-data)).

## Fedora / openSUSE / RHEL (`.rpm`)

```bash
# Fedora / RHEL
sudo dnf install ./grapestrap-<version>.x86_64.rpm

# openSUSE
sudo zypper install ./grapestrap-<version>.x86_64.rpm
```

**Uninstall:** `sudo dnf remove grapestrap`.

## AppImage (universal)

```bash
chmod +x GrapeStrap-<version>.AppImage
./GrapeStrap-<version>.AppImage
```

Runs in place — no root, no install, no system changes. For launcher-menu
integration and the `.gstrap` association, use
[AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher) or
create a `.desktop` entry by hand from the template at
`packaging/desktop/grapestrap.desktop` (point `Exec=` at the AppImage path).

## Tarball (`tar.gz`)

```bash
mkdir -p ~/opt
tar -xzf grapestrap-<version>.tar.gz -C ~/opt/
~/opt/grapestrap-<version>/grapestrap
```

Optional launcher symlink:

```bash
ln -s ~/opt/grapestrap-<version>/grapestrap ~/.local/bin/grapestrap
```

**Uninstall:** delete the extracted directory (and the symlink).

## Building from source

Requires Node.js 20+, npm 10+, git.

```bash
git clone https://github.com/juhriah-ops/grapestrap.git
cd grapestrap
npm install
npm start                # run the editor from the working tree
```

Package builds (output lands in `release/`):

```bash
npm run build:linux      # deb + rpm + AppImage + tar.gz
npm run build:deb        # single format
npm run build:rpm        #   (rpm needs the `rpm` package installed:
npm run build:appimage   #    sudo apt install rpm)
npm run build:tarball
```

Test suite and lint:

```bash
xvfb-run -a npx playwright test   # full e2e suite (drives dist/main/main.js
                                  #  — run `npm run build` first)
npm run lint
```

## Wayland

GrapeStrap auto-detects the session type at startup
(`src/main/platform/wayland.js`): a Wayland session (via
`XDG_SESSION_TYPE=wayland` or a set `WAYLAND_DISPLAY`) enables the native
Ozone Wayland backend (`ozone-platform-hint=auto`,
`UseOzonePlatform,WaylandWindowDecorations`); anything else runs plain X11.

Overrides:

```bash
GRAPESTRAP_FORCE_X11=1 grapestrap       # never Wayland, even if detected
GRAPESTRAP_FORCE_WAYLAND=1 grapestrap   # always Wayland (debugging)
```

## `.gstrap` MIME registration

The `.deb` and `.rpm` install
`/usr/share/mime/packages/grapestrap.xml` (generated by electron-builder
from the project's file-association config), which maps `*.gstrap` to
`application/x-grapestrap`; the package post-install script runs
`update-mime-database` and `update-desktop-database`. Double-clicking a
`.gstrap` file in Files/Dolphin/Thunar then opens it in GrapeStrap.

AppImage and tarball installs don't touch the system — register manually if
you want the association:

```bash
sudo cp packaging/desktop/grapestrap-mime.xml /usr/share/mime/packages/
sudo update-mime-database /usr/share/mime
xdg-mime default grapestrap.desktop application/x-grapestrap
```

(`packaging/desktop/grapestrap-mime.xml` is the canonical, richer MIME
definition kept for distro packagers.)

Verify:

```bash
xdg-mime query default application/x-grapestrap
# expected: grapestrap.desktop
```

## XDG paths — where GrapeStrap writes

GrapeStrap is strict about the XDG Base Directory spec. The resolver is
`src/main/platform/xdg.js`; env vars are honoured, with the standard
fallbacks (`~/.config`, `~/.cache`, `~/.local/share`, `~/.local/state`).

| Path | Contents |
|------|----------|
| `$XDG_CONFIG_HOME/GrapeStrap/preferences.json` | preferences |
| `$XDG_CONFIG_HOME/GrapeStrap/plugins/` | user-installed plugins |
| `$XDG_CONFIG_HOME/GrapeStrap/snippets/` | snippets library |
| `$XDG_CACHE_HOME/GrapeStrap/preview/<slug>/` | Preview-in-Browser export cache, one dir per project (created on first preview) |
| `$XDG_DATA_HOME/GrapeStrap/logs/` | `main.log` — attach when filing bugs |
| `$XDG_DATA_HOME/GrapeStrap/plugin-data/` | per-plugin data dirs |
| `$XDG_DATA_HOME/GrapeStrap/recovery/` | **unused** — created at startup but nothing writes here (known dead entry in `xdg.js`; crash-recovery snapshots actually live next to the project, below) |
| `$XDG_STATE_HOME/GrapeStrap/workspaces/` | saved workspace layouts |
| `$XDG_STATE_HOME/GrapeStrap/recent-projects.json` | recent-projects list |
| `$XDG_STATE_HOME/GrapeStrap/session.json` | session state |

**Project files are never stored under XDG** — they live wherever you save
them. Crash-recovery snapshots are written next to the project manifest as
`<project>.gstrap.recovery`.

### Removing user data

```bash
rm -rf ~/.config/GrapeStrap ~/.cache/GrapeStrap \
       ~/.local/share/GrapeStrap ~/.local/state/GrapeStrap
```

(Substitute your `$XDG_*` overrides if set.) This never touches project
files.

## Verifying releases

Releases are currently **unsigned**; CI builds them from the tagged commit.
Verify by building from source and comparing, or inspect the artifacts
(`dpkg -c`, `rpm -qlp`). Checksums/signing are planned post-v0.1.0.

## Troubleshooting

**`error while loading shared libraries: libnss3.so`** (AppImage/tarball):
install the Electron system libraries listed under
[System requirements](#system-requirements).

**`.gstrap` files don't open from the file manager:** re-run the manual
registration from [MIME registration](#gstrap-mime-registration).

**Wayland looks blurry / behaves like X11:** force the backend with
`GRAPESTRAP_FORCE_WAYLAND=1` (or fall back with `GRAPESTRAP_FORCE_X11=1`)
and file an issue with your compositor name and `echo $XDG_SESSION_TYPE`.

**Where are the logs?** `$XDG_DATA_HOME/GrapeStrap/logs/main.log`
(default `~/.local/share/GrapeStrap/logs/main.log`).
